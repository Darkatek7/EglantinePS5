Repeated room performance
Platform: BC250, Bazzite Deck, RADV GFX1013, Mesa 26.2.1. Both arms use the
same -O3 -g -DNDEBUG -fno-omit-frame-pointer build flags, 1x handheld resolution,
NoSharpen, Fast GPU accuracy, frame generation off, and FSR/DLSS off. The normal
hardware/affinity policy is retained. The default AppImage build remains O2;
O3 alone previously showed no meaningful improvement.

Only 5baf6924682d91c5ea3d43ee41fee892bb6c8489 (A) and
3167500739d836b56811cb20b720c618dca1508c (B) were compared here. These are NOT
measurements of the later counter-reset candidate.

Runs were sequential A1/B1/A2/B2, with independent profiles and the same room
checkpoint. Each actual camera image was reviewed before measurement. Wait
until game uptime >=250 s, after scheduled startup images, then settle 30 s.
Read 61 guest vi2 present counters about one second apart; midpoint RPC times
give 61.23-61.33 s windows. Then issue a SEPARATE 60 s frame_times query. No
inputs, screenshots, profiling, RenderDoc or verification flags run inside
either measured window. The debug endpoint remains enabled. Other emulator
checks were empty, and each owned process ended with focus restored.

Unweighted arm means: counter 28.1485 vs 28.4316; independent frame-times

intervals; those intervals are not a complete trace. BC250-ZELDA-ROOM.json
preserves the counter intervals and whole-window summaries without host or
game-file paths. These results describe this room view, not a full-playthrough
average or a PS5 result.

Validation scope
On 3167500, separate diagnostic sessions checked 3,660,539 fast-draw candidates
with zero reported pipeline/view/binding mismatches, then 13,350,393 uniform
comparisons and 3,520,512 descriptor comparisons with zero reported mismatches.
The second session left FAST_DRAW_VERIFY unset to exercise actual delta
preparation. Diagnostic timing is excluded from the performance table.
FAST_DRAW_VERIFY forces full preparation; all three verifiers inspect their
specific binding/resource invariants, not Vulkan query result values. These
results do not qualify the subsequent counter-reset change.

variant tested with production engine objects and matching static libraries.

The 3167500 negative control passes 248 of those assertions and fails exactly
48 new serial/reuse expectations; reset dispatch, shadow/dirty updates and
deferred-instance ordering already pass. The observer's model counter proves
engine ordering, not real Vulkan query accumulation or fence completion.
This is a focused suite, not an assertion that every project test ran.

Remaining rendering defect
Purple/lavender forest soil is reproducible in the fresh opening on earlier
builds and 5baf692. A native capture first fills the affected soil in pass 59,
draw interval [519,633): 114 draws. The decoded exports contain no NaN/Inf.
That pass's 32-shader-hash cap and 118 skipped compressed sampled inputs leave
the exact draw, shader, texture and cause unresolved. Native capture forces
full draw preparation during the captured frame; earlier persistent state
is not excluded. A normal RenderDoc capture has a different cinematic camera
and cannot serve as a matched negative or establish a RenderDoc-induced fix.
Raw captures, game images, saves, keys, firmware and dumps remain private.
